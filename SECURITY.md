# Безопасность

## Важно перед использованием

**Ограничения путей файловых инструментов не являются песочницей для shell.** Команда в терминале или через `run_command` может обращаться ко всему, что доступно приложению. При включённом root команда выполняется с правами суперпользователя и может повредить систему или удалить данные. Проверяйте каждое действие до подтверждения, используйте резервные копии и не включайте root или авто-подтверждение без необходимости.

Модель и содержимое проекта могут предлагать вредоносные действия или команды. Не считайте содержимое файлов, веб-страниц и ответы модели доверенными инструкциями. Подтверждение уменьшает риск, но не заменяет проверку.

## Данные и подключения

- Ключи API хранятся в настройках, зашифрованных ключом Android Keystore; автоматический Android backup приложения отключён. Не публикуйте ключи, журналы с ними или файлы подписи.
- История сессий, сообщения, результаты инструментов, рассуждения и подписи провайдера хранятся локально в JSON **без шифрования приложением**. Не помещайте в неё секреты, если это неприемлемо для устройства и его модели угроз.
- Выбранному провайдеру передаются сообщения и результаты инструментов для работы агента. Проверьте его политику хранения, регионы и тариф. Подписанные блоки Anthropic возвращаются только исходному провайдеру, адресу и модели; текст рассуждений других провайдеров в историю запроса не добавляется.
- Для публичных API требуется HTTPS. HTTP разрешён только для локальных адресов без API-ключа; передаваемые через него данные не зашифрованы.
- Release должен быть подписан постоянным ключом владельца. CI использует временный тестовый ключ, а debug-сборки не являются production-релизами. См. [документ о релизе](docs/RELEASE.md).

## Сообщить об уязвимости

Если в репозитории включены приватные security advisories, используйте **Security → Report a vulnerability** на GitHub. Иначе свяжитесь с владельцем по доступному приватному каналу, прежде чем открывать публичный issue. Не прикладывайте ключи, личные данные или инструкции эксплуатации в открытый issue. Владелец ещё должен указать постоянный канал и политику ответа на сообщения.

Проект находится в разработке и не проходил независимый аудит. Исправления и сроки поддержки конкретных версий пока не гарантированы.
