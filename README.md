# OpenCode Mobile

Android-приложение — ИИ-агент для программирования: чат с моделью, работа с файлами, команды в shell и опциональный root. Kotlin + Jetpack Compose; агент и файловые инструменты работают на устройстве, а модель может быть локальной или доступной по API.

## Установка и запуск

Новая сборка рассчитана на **Android 7.0 / API 24 и выше**, root не обязателен. Нужны JDK 17 и Android SDK с API 35:

```bash
./gradlew :app:assembleDebug
./scripts/install-emulator.sh app/build/outputs/apk/debug/app-debug.apk
```

На GitHub во вкладке **Actions → Build APK** выберите успешный запуск вашей ветки и скачайте артефакт `opencode-mobile-debug`. Распакуйте ZIP и устанавливайте находящийся внутри `app-debug.apk`, не ZIP. Существующий [релиз v0.1.0](https://github.com/ccndjfgjs/Dustin-Fisher-Murphy/releases/tag/v0.1.0) — старая debug-сборка: она поддерживает только Android 8+ и не является production-релизом.

Debug-приложение имеет отдельный пакет `dev.opencode.mobile.debug`, так что может сосуществовать со старой или релизной версией. В CI debug-ключ может меняться от сборки к сборке; при ошибке несовпадения подписи не удаляйте установленное приложение, пока не сохранили нужные данные. Подробные шаги, типичные ошибки установки и адреса эмулятора — в [docs/RELEASE.md](docs/RELEASE.md).

## Сертификат и релиз

Для установки Android APK должен быть подписан, но покупать или вручную устанавливать SSL-сертификат не нужно. Владелец создаёт собственный постоянный ключ подписи и хранит его вне репозитория. Для подписанных APK и AAB подготовлена сборка через переменные окружения и GitHub Actions; при отсутствии ключа release не публикуется. Создание ключа, публичного сертификата, резервная копия и настройка CI описаны в [docs/RELEASE.md](docs/RELEASE.md). Тестовые/debug-ключи нельзя использовать как production-ключ.

## Возможности

- Чат и цикл агента с OpenAI-совместимыми API и Anthropic; потоковый вывод, остановка и локальная история сессий.
- Чтение, поиск, создание и редактирование файлов; терминал, `run_command`, `web_fetch`, план задач и сведения об устройстве.
- Подтверждение действий, изменяющих файлы или запускающих команды; сетевой `web_fetch` также требует подтверждения. Авто-подтверждение по умолчанию выключено.
- Root (`su`) по умолчанию выключен и включается пользователем в настройках. В обычном режиме действуют права Android-приложения.
- Настройки, включая API-ключи, шифруются ключом Android Keystore; старые настройки мигрируются при первом запуске. Системное резервное копирование приложения отключено. Публичные сетевые провайдеры требуют HTTPS; локальный HTTP доступен только без API-ключа и передаёт данные незашифрованными.

## Первый запуск

1. Разрешение на общие файлы опционально; без него приложение использует собственную папку. Для `/sdcard` на Android 11+ требуется «Доступ ко всем файлам», на Android 7–10 — разрешение на хранилище.
2. В **Настройки → Провайдер** укажите адрес, модель и при необходимости API-ключ. Для Ollama на компьютере из стандартного Android Emulator используйте `http://10.0.2.2:11434/v1`; `127.0.0.1` означает сам эмулятор.
3. Выберите папку проекта, начните чат и внимательно проверяйте запрашиваемые инструментами действия. Root включайте только если понимаете последствия.

## Проверка и ограничения

```bash
./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
./gradlew :app:connectedDebugAndroidTest  # запущенный эмулятор или устройство
```

CI проверяет unit-тесты, lint, установку и запуск на эмуляторах API 24/35, а также подписание release временным тестовым ключом. Реальный production-ключ остаётся у владельца.

Это всё ещё развивающийся проект, а не сертифицированный продукт. Подписание и тесты не гарантируют готовность к публикации: необходимы ревью безопасности, проверка реальных устройств, соответствия требованиям магазина и политики конфиденциальности. Команды и root могут повредить данные; ограничения путей инструментов не являются полноценной песочницей для произвольной shell-команды. Модель получает введённые сообщения и результаты инструментов, а выбранный провайдер обрабатывает переданный ему контент. [Архитектура](docs/ARCHITECTURE.md).
