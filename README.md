# OpenCode Mobile

Android-приложение — **ИИ-агент для программирования в духе [opencode](https://github.com/sst/opencode)**,
который работает прямо на телефоне: читает и правит файлы, запускает shell-команды,
собирает проекты и может выполнять привилегированные действия через **root (`su`)**.

Kotlin + Jetpack Compose, без серверной части: весь агент, инструменты и файловая система — на устройстве.

---

## Что уже есть

### Агент (agent loop)
- Цикл «модель → вызов инструмента → результат → модель» с лимитом шагов.
- Потоковый вывод ответа (SSE) и живой вывод команд.
- План работы (`todo_write`) отображается в чате.
- Подтверждение опасных действий (можно отключить в настройках).
- Остановка генерации/команды в один тап.
- История сессий сохраняется локально (JSON в `filesDir/sessions`).

### Инструменты (аналог opencode tools)
| Инструмент | Назначение |
|---|---|
| `read_file` | чтение файла с нумерацией строк |
| `write_file` | создание/перезапись файла |
| `edit_file` | точечная замена фрагмента (с проверкой уникальности) |
| `list_dir` | содержимое папки с глубиной |
| `glob` | поиск файлов по шаблону |
| `grep` | поиск по содержимому (regex) |
| `run_command` | shell-команда, при root — через `su` |
| `delete_path` / `move_path` | удаление и перемещение |
| `todo_write` | ведение плана |
| `web_fetch` | загрузка страниц/документации |
| `device_info` | Android, ABI, root, SELinux, свободное место |

### Root и shell
- Определение `su` (Magisk / KernelSU / APatch), версия и SELinux.
- `su -c` с рабочей папкой, таймаутами и отменой.
- Fallback-чтение/запись системных файлов через root (temp + `cp`).
- Встроенный терминал: обычный shell или `su`, история вывода.
- Без root приложение работает в песочнице: доступ ограничен рабочей папкой и `/sdcard`.

### Модели
- **Облако по API-ключу:** OpenAI, Anthropic, OpenRouter, любой OpenAI-совместимый endpoint.
- **Локально:** Ollama (`http://127.0.0.1:11434/v1`), LM Studio по LAN, llama.cpp server.
- Настройка провайдеров и моделей прямо в приложении; ключи хранятся только на устройстве.

### Рабочее пространство
- Файловый менеджер с открытием файлов во встроенном редакторе.
- Создание файлов и папок, сохранение правок.
- Быстрый переход «папка → новая сессия агента».

## Сборка

### Через GitHub Actions (ничего устанавливать не нужно)
Любой push в `main` или `arena/**` собирает APK:

1. Открой вкладку **Actions** → workflow **Build APK**.
2. Возьми артефакт **opencode-mobile-debug** — внутри `app-debug.apk`.

Для публичной сборки поставь тег — APK прикрепится к GitHub Release:

```bash
git tag v0.1.0 && git push origin v0.1.0
```

### Локально
Нужны JDK 17 и Android SDK (compileSdk 35).

```bash
./gradlew :app:assembleDebug
# APK: app/build/outputs/apk/debug/app-debug.apk
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

## Первый запуск

1. **Файлы:** выдай «Доступ ко всем файлам», чтобы работать в `/sdcard` (иначе рабочая папка будет внутри приложения).
2. **Настройки → Провайдер:** выбери провайдера, вставь API-ключ и модель.
   - Для локальной модели запусти Ollama на телефоне (Termux) или на ПК и укажи `http://IP:11434/v1`.
3. **Root (опционально):** установи Magisk/KernelSU, выдай приложению `su`. Проверка — в «Настройках» или в терминале (`id` → `uid=0`).
4. Открой папку проекта и напиши задачу в чат.

Примеры задач:
- «Прочитай проект, найди ошибку сборки и исправь её»
- «Напиши Telegram-бота на Python и запусти его в фоне»
- «Сделай git commit с осмысленным сообщением и покажи diff»
- «Установи пакет, настрой окружение, проверь, что сервис стартует»

## Архитектура

```
app/src/main/java/dev/opencode/mobile/
├─ OpenCodeApp.kt            Application: prefs + storage
├─ MainActivity.kt           Compose entrypoint
├─ agent/AgentEngine.kt      цикл агента, системный промпт, лимиты
├─ ai/AiClient.kt            OpenAI-совместимый и Anthropic клиенты (SSE)
├─ data/                     модели, настройки, хранилище сессий
├─ shell/Shell.kt            su/shell, чтение-запись с root-fallback
├─ tools/Tools.kt            реестр инструментов + JSON-схемы
└─ ui/                       Compose-экраны и ViewModel
```

Уровни выполнения команд: `root (su)` → `shell от uid приложения`.
Режим выбирается в настройках и показывается в чате чипом `root` / `shell`.

## Безопасность

- API-ключи не покидают устройство и не логируются.
- Опасные инструменты (`write_file`, `edit_file`, `run_command`, `delete_path`, `move_path`)
  по умолчанию требуют подтверждения.
- Команды выполняются с таймаутом; вывод ограничивается по размеру.
- Приложение не содержит бэкдоров и не отправляет данные на сторонние серверы, кроме выбранного API модели.
