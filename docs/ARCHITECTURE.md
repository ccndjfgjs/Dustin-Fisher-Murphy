# Архитектура OpenCode Mobile

```text
Compose UI → AppViewModel → AgentEngine → AiClient (OpenAI-совместимый / Anthropic)
                                  ├── Tools
                                  ├── Shell (обычный / явно разрешённый su)
                                  └── SessionStore / Prefs
```

- `AgentEngine` локально сжимает длинную историю с потерей деталей, сохраняя оригиналы и целые группы вызовов/результатов, и выполняет цикл «модель → инструмент → результат». Прерванные вызовы дополняются служебными результатами при повторной отправке.
- MCP ограничен Streamable HTTP 2025-03-26 и инструментами: конфигурация и Bearer-токен защищены Keystore, каждый вызов отдельно подтверждается. План блокирует MCP и Git-процессы; не следует подключать недоверенные серверы.
- Git использует внешний доверенный бинарный файл без root. Коммит только подготовленного индекса проверяется по diff и OID до и после подтверждения. Проверка не изолирует параллельные изменения другого процесса; hooks и подпись выключены.
- `AiClient` поддерживает SSE и обычный JSON. API-ключи не отправляются по HTTP; незашифрованный HTTP разрешён лишь для локальных адресов и без ключа.
- `Tools` описывает схемы и реализации инструментов. Запись и `web_fetch` требуют подтверждения, если не включено автоматическое; shell, MCP и Git-коммит подтверждаются всегда. При включённом MCP автоодобрение изменяющих инструментов отключено. План разрешает только проверенный список чтения и локальный todo. При рекурсивном поиске символические ссылки не обходятся.
- `Shell` по умолчанию не повышает привилегии; fallback через `su` возможен только при включённом root. Выполнение не интерактивно, вывод ограничен, доступен таймаут. Уничтожение родительского shell-процесса не гарантирует завершение всех созданных им дочерних процессов.
- `Prefs` шифрует JSON настроек с помощью AES-GCM и ключа Android Keystore. При миграции старый открытый JSON удаляется только после успешного сохранения зашифрованной версии. При ошибке Keystore сохранённые данные не перезаписываются и пользователь видит предупреждение.
- `SessionStore` использует `AtomicFile` для сохранения истории, чтобы не терять предыдущую версию файла при прерывании записи. Сессии не зашифрованы отдельно и доступны приложению на устройстве.

Сетевые запросы и команды выполняются вне UI-потока; события интерфейса доставляются на главный поток. Переключение сессии во время активного запуска запрещено, пока задача не остановлена.

## Границы безопасности

Проверка путей файловых инструментов снижает риск случайного выхода за разрешённые каталоги, но не является механизмом изоляции. С разрешения пользователя shell-команда может обращаться ко всему, что доступно её Android UID или root, а модель получает результаты инструментов. Поток HTTP в локальной сети не шифруется. Устройства с root, отладочными возможностями или вредоносным ПО могут иметь доступ к данным приложения. Для production необходим отдельный аудит безопасности и приватности.
